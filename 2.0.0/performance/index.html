    Performance¶

    This page records the retained public cross-engine benchmark for ApexBase v2.0.0. It is a reproducible snapshot, not a universal claim: rerun the suite on your own hardware and workload before drawing conclusions.

    v2.0.0 public snapshot¶

    • Date / source: 2026-11-03, v2.0.0 release tree (commit 426424a)
    • Baseline protocol: median of three same-machine runs (benchmarks/latest_public_baseline.json, baseline_meta.samples = 3)
    • System: macOS 27.0.1, Apple arm64 (10 cores), 32 GB RAM
    • Runtime stack: Python 3.12.2, ApexBase 2.0.0, SQLite 3.46.0, DuckDB 1.1.3, PyArrow 23.0.1, sqlite-vector 1.0.0
    • Build: rustc 1.92.0, maturin 1.9.1, release profile
    • Tabular dataset: 1,000,000 rows × 5 columns
    • Vector dataset: 1,000,000 Float32 vectors × 128 dimensions, k=10, 10 exact batch queries
    • Quantized module: 1,000,000 rows, 20 queries, candidate_k=100, seed 20260821
    • Method: ApexBase result cache disabled, 2 warmup iterations + 5 timed iterations, materialized results
    • Retained report: benchmarks/latest_public_baseline.json

    The suite completes all 119 named rows: 105 tabular, 6 exact-vector, and 8 quantized precision rows. Every row with a direct competitor is won — 117/117 comparable: 105/105 tabular, 6/6 exact vector, and 6/6 quantized codecs shared with sqlite-vector. Float16 and BFloat16 are ApexBase-only quantized formats and are excluded from the comparable total.

    Exact vector similarity 6 6 0 0
    Quantized vector, shared codecs 6 6 0 0

    Quantized vector retrieval¶

    The quantized module keeps the source Float32 vector as the authoritative column, scans a compressed accelerator for candidates, and optionally rescans the source vector for exact reranking. Twenty queries, k=10, candidate_k=100, batch-amortized latency per query.

    Reproduce¶

    Run the same default public profile:

    python benchmarks/bench_vs_sqlite_duckdb.py \
  --output benchmarks/results/public.json

    Use --skip-vector for a tabular-only run or --skip-quantized-vector to keep exact-vector metrics while omitting the compressed module. The unified command accepts --rows, --warmup, --iterations, --vector-rows, --vector-dim, and the --quantized-vector-* options when a different workload is required.

    benchmarks/latest_public_baseline.json is the maintained baseline. Rebuild it from at least three same-machine runs so a single noisy run cannot move it:

    python benchmarks/rebuild_public_baseline.py \
  --input run1.json run2.json run3.json \
  --output benchmarks/latest_public_baseline.json

    The quantized benchmark requires the optional sqliteai-vector Python package and a Python build linked against a compatible SQLite version.

    Methodology and limits¶

    • Results are workload-sensitive. A lower row count, a different Python build, or a different CPU changes absolute latency; compare shapes and ratios rather than single numbers.
    • The public suite is a cross-engine scoreboard, not ApexBase's own regression gate. Regressions are caught by the same-machine base/current guard in benchmarks/run_local_perf_guard.py and the canary in benchmarks/bench_perf_canary.py.
    • SQLite rows use the sqlite-vector extension for ranked vector metrics; without the extension, those rows are reported as unavailable rather than estimated.
    • All reports are retained as JSON, including config, system, build, and dependency metadata, so a result can be audited after the fact.

    History¶

    v1.x snapshots (v1.35.0, v1.34.0, v1.30.0) remain in the release notes and the git history. This page is kept in sync with benchmarks/latest_public_baseline.json; when the maintained baseline is rebuilt, the snapshot section above is updated with it.
